# Редактор гліфів Verba

Локальний застосунок macOS 14+ на AppKit/WKWebView. Працює без сайту, Worker,
інтернету, Electron або встановлення Python. Читає всі 2 266 шрифтових записи
поточного корпусу; читання гліфів іде сторінками через обмежений кеш.

## Огляд гліфів і бібліотеки (0.12.0)

Основна зона — прокручуваний огляд усього шрифту, без сторінок. Рендеряться лише
видимі рядки та невеликий запас; план рядків кешується. Клік обирає символ,
подвійний клік або **«Редагувати вибраний…»** відкриває другорядну панель.
Стрілки в огляді переміщують вибір; у відкритому редакторі — пікселі.

Групи можна вмикати незалежно й одночасно. Увімкніть **Латиниця + Українська**
та **«Показати групи разом»**: обидві абетки розташовані поруч, у паралельних
колонках з окремими секціями великих і малих. Перемикачі **Великі / Малі**
фільтрують регістр. Підписи кожної літери містять абетку й регістр. Налаштування
груп, регістру й режиму перегляду зберігаються в сеансі.

**«Бібліотека гліфами»** показує шрифти через справжні растрові зразки вибраних
груп, включно з поточними правками. Кожна вибрана секція показана повністю:
26 латинських або 33 українських літери на регістр. Картки переносять гліфи
на наступні рядки й мають природну висоту; адаптивна сітка використовує одну
або дві колонки. Весь шрифт відкривається кліком на назві. Відсутні групи явно позначені;
для шрифтів без Unicode-мапи показано підписаний зразок вихідних числових кодів. Картки віртуалізовані; кеш даних бібліотеки
обмежений 4 MiB, до 32 підготовлених зразків, запити за межами видимої зони
скасовуються. Кеш редактора залишається окремим, 8 MiB.

## Пакетне доповнення та перевірка референсів (0.14.0)

Генерація української потребує непорожніх латинських гліфів із явною Unicode-мапою
відповідного регістру. Без великих латинських не генеруються великі українські;
аналогічно для малих. Сирі числові коди, грецькі знаки, OCR-здогадки й немаповані
растри не стають латинськими референсами автоматично. UI показує причину блокування;
черга **«Бракує латинських референсів»** допомагає знайти такі шрифти. За потреби
спочатку перевірте й застосуйте ASCII-мапу. Python-провайдер перевіряє ту саму умову.

Локальна перевірка поточного знімка 2026-11-07: залишено **114 757** нових гліфів;
**1 848** шрифтів мають усі 66 українських літер, **418** очікують належних
латинських референсів, **26 407** українських літер лишаються відсутніми.
Початкові 586 непорожніх правок і 11 документів із нотатками збережено; SHA всіх
2 266 джерел незмінні. 26 407 попередніх доповнень без належного латинського
референсу вилучено. Нові гліфи позначені як такі, що потребують візуальної перевірки;
це перевірка структури/походження, а не підтвердження художньої якості кожного знака.

Підготовка й генерація не змінюють правки. Застосування отримує той самий `flock`,
що й редактор, робить резервну копію та звіряє SHA запиту з відповіддю. Наявні
непорожні гліфи не замінюються. Закрийте проєкт у редакторі перед застосуванням.

```sh
node desktop/glyph-editor/bulk-ukrainian.mjs prepare \
  --corpus app --project "$GLYPH_PROJECT" --stage "$GLYPH_STAGE"
python3 desktop/glyph-editor/experiments/complete_ukrainian.py \
  --stage "$GLYPH_STAGE" --data desktop/glyph-editor/.build/style-transfer --workers 4
node desktop/glyph-editor/bulk-ukrainian.mjs apply \
  --corpus app --project "$GLYPH_PROJECT" --stage "$GLYPH_STAGE"
```

`manifest.json` містить дозволені й заблоковані цілі, `applied.json` — результат,
`specimens/` — фактичні латинські/українські растри. Шлях резервної копії записаний
у `apply-backup.json`. Звіт, локальні правки й растри не входять до Git.
Для візуального перегляду відкрийте **«Бібліотека гліфами»**, увімкніть
**Латиниця + Українська** й обидва регістри.

Профілювання повної бібліотеки та виправлені проблеми описані в
[PERFORMANCE.md](PERFORMANCE.md). Лічильники використовують невеликий відновлюваний
кеш знімка/розміру/часу зміни/inode файлів; повна валідація конкретного документа
виконується під час його відкриття і збереження.

## Життєвий цикл документа (0.14.1)

Керування відкриттям і збереженням відокремлено від UI. Збереження перед
перемиканням чи закриттям чекає також на правки, які надійшли під час запису.
Помилка запису залишає документ незбереженим для повторної спроби; помилка
відкриття не прибирає поточний документ. При швидкому виборі шрифтів застосовується
останній запит, а його запізнілі попередники ігноруються. Записи сеансу
впорядковані, тому старий відкладений запис не перезаписує останній вибір.

`document-controller.ts` містить чергу записів і бар’єр збереження,
`font-document.ts` — завантаження й підготовку знімка, `font-library.ts` — пошук,
фільтри й прогрес. У сортуванні повторно використовується один `Intl.Collator`;
пошукові рядки підготовлюються один раз. Застарілий фільтр у сеансі відновлюється
як **«Усі шрифти»**.

## Навігація й перегляд (0.14.2)

Черги, відновлення вибору й асинхронне читання гліфа винесено в
`glyph-navigation.ts`. Вибір прив’язаний до ключа символу; зміна Unicode-мапи чи
растра під час читання спричиняє повторне читання, запізнілий результат не
змінює полотно. Швидкі стрілки в огляді враховують уже запитану позицію.
PageUp/PageDown рахують кроки від запитаного шрифту.

«Лише непереглянуті» зберігається в сеансі та враховує Unicode-ключі й ID гліфів;
галерея та інспектор показують однакову позначку. Review чекає завершення
вставлення/перенесення. Порожня черга очищує полотно. «Далі» на останньому гліфі
переходить до наступного шрифту, якщо він є в поточному фільтрі. Кінець черги
не відкриває повторно останній шрифт. При помилці читання старий гліф лишається
доступним лише якщо він належить поточній черзі.

## Зворотний зв’язок OCR · експеримент

У вікні доповнення ввімкнено **«Перевіряти читабельність через OCR»**.
Розпізнавання працює локально через Tesseract C API, без передавання зображень.
Один екземпляр мовної моделі та кеш розпізнаних растрів використовуються для
всього пакета. Очікувана літера не передається розпізнавачу як whitelist.
Перед ранжуванням він перевіряється на до 12 відомих латинських символах
референсу; потрібно щонайменше 4 зразки та 60% впевнених збігів або перевірених
латинсько-кириличних двійників. Регістр не ігнорується.

При успішному калібруванні впевнені збіги йдуть перед непевними, а явні
помилкові розпізнавання опускаються нижче. Точні копії та двійники захищені;
жоден варіант не видаляється. При слабкому OCR порядок зберігається, а оцінки
показано як непевні. Бал OCR — оцінка моделі, а не ймовірність правильності
й не оцінка стилістичної відповідності. Слабке читання дрібних bitmap-шрифтів —
очікуване обмеження, тому OCR не є обов’язковим бар’єром застосування.

Потрібна локальна бібліотека Tesseract 5; мовні файли підготовлює
`python3 desktop/glyph-editor/experiments/setup_ocr.py`. Офіційні ukr/eng
`tessdata_fast` закріплені commit/SHA-256, Apache-2.0, у виключеній із git
`.build/ocr/`; відсутність OCR не блокує редактор чи генерацію. Оцінка зберігається
в походженні застосованого варіанта. У локальній перевірці 24 випадків у чотирьох
шрифтах OCR пройшов калібрування у шести випадках, змінив порядок у п’яти;
решту залишив без змін. Це перевірка механізму, не доказ загального поліпшення
якості. Звіт залишається локально в `.build/ocr/feedback-report.json`.

## Єдина моноширинна комірка (0.13.0)

Усі гліфи поточного шрифту мають однакові width/height/rowBytes, крок і базову
лінію комірки: наявні, порожні, створені та згенеровані. Вузькі джерельні
растри `I` та широкі `W` не задають окремих розмірів редагування. Звичайні
знаки вирівнюються по baseline й доповнюються порожніми пікселями; під час
переходу з різних cropped advances їх розташування центрується в спільному
кроці. Растри безпосередньо не згладжуються. Наприклад, усі літери PolarSmall
редагуються в `8×6`, а службовий банер `98×6` не розтягує комірку решти літер.

Початкова комірка визначається один раз із вихідного алфавіту, незалежно від
вибраної групи або чергової правки. **«Розмір для всього шрифту»** та
**«Крок для всього шрифту»** змінюють спільні параметри, одним Undo; `fontCell`
зберігається в правках. Огляд, інспектор, текстовий зразок, бібліотека,
автозаповнення та експорт використовують цю саму комірку. Експорт має
`cell.monospace=true` і однакові розміри та advance всіх гліфів.

Службові графічні растри, чий намальований вміст більший за комірку, вміщуються
nearest-pixel масштабуванням зі збереженням пропорцій. Це може втрачати дрібні
деталі великих зображень; джерельні файли та їх SHA не змінюються, оригінали
залишаються в корпусі. Звичайні літери отримують padding/зсув без ресемплінгу.

Коли вибрана абетка не має жодного наявного гліфа, відкривається латинка або
всі вихідні гліфи. Явний вибір української черги показує місця для її доповнення.
Classic 18-point містить 192 непорожні гліфи, але джерело не має Unicode-мапи.
Кнопка **«Задати ASCII-мапу…»** показує підписаний піксельний зразок перед
застосуванням 0x20–0x7E як ASCII. Мапа зберігається тільки в правках; неоднозначні
коди/конфлікти пропускаються, пікселі та оригінальні числові коди зберігаються.
Уся мапа скасовується одним Undo. Редактор не вгадує кодування автоматично.

## Доповнити українську з наявної латинки (0.12.0)

Відкрийте шрифт і натисніть **«Доповнити українську з латинки…»** праворуч.
Редактор бере до 52 наявних латинських літер з поточними правками та шукає
відсутні/порожні українські гліфи для всіх 66 літер. Двадцять перевірених
двійників (`A→А`, `H→Н`, `I→І`, `a→а` тощо) отримують перший варіант з
пікселів цієї ж латинки, вирівняних за baseline/початком пера. Далі йдуть нативні дзеркала/повороти (`N→И`, `R→Я`, `V→Л`, `U→П`, `L→Г`, `P→Ь`) та композиції Ж/Ю/Є з латинських штрихів. Повороти зберігають padding і baseline. Для решти та як альтернативи пропонуються retrieval-заготовки зі схожих шрифтів. Дотренування не потрібне; CNN у цьому
режимі не запускається. Порівняння референсного стилю кешується на весь пакет.

Кнопки літер перемикають перегляд, картка обирає варіант, «Пропустити» знімає
вибір. Перші варіанти попередньо обрані для перегляду; **запис відбувається
тільки після «Застосувати вибрані»**. Увесь пакет — один undo. Наявні непорожні
українські гліфи за замовчуванням пропускаються; латинські не змінюються.

**«Інший референс / літери…»** дозволяє вибрати шрифт із каталогу, конкретні
референсні символи або локальний файл: Para Font/Glyph JSON, Para Glyph Region,
Unicode BDF, TTF/OTF. Можна зняти окремі гліфи референсу та ввести власний
список потрібних літер. До 64 референсів і 128 цілей за пакет; bitmap-комірки
та гліфи до 1024 px на вісь і 262144 пікселів на растр.
Імпортовані локальні референси обмежені 256×256. BDF/JSON зберігають пікселі, TTF/OTF раструється в 1 bit
без згладжування у вибраному розмірі 6–24 px. Покриття TTF/OTF визначається
явною Unicode cmap; BDF потребує ISO10646. Позначення символів не вгадуються.
Файли й гліфи залишаються локальними. Для імпорту TTF/OTF потрібен fontTools.

Референс впливає на підбір/копію, а результат записується у відкритий шрифт.
Метрики й Unicode наявних цілей зберігаються. В експорті є походження донора,
референсний шрифт/SHA, хеш фактичного набору референсних гліфів і source/target
символи. ID гліфів чужого референсу не ремапляться як локальні.

Для окремого тестового вікна підтримується `--demo-latin --project <папка>`;
демо-пакет може задати `demoLatin` та `projectRoot` у configuration.json.
Він автоматично відкриває перегляд, без застосування. У сесії перевірено Acer
VGA 8×8: 66 українських літер одним undo, 20 точних копій з латинки, вихідні
256 гліфів незмінні, експорт пройшов канонічну валідацію. Пакет мав 1.4 MiB
відповіді та близько 0.20 s роботи провайдера (без запуску Python/читання даних).

## Запуск

```sh
# У корені репозиторію; app/node_modules після npm ci в app.
node desktop/glyph-editor/build.mjs
```

Відкрити `desktop/glyph-editor/dist/Verba Glyph Editor.app` у Finder.
Збірка прив’язує застосунок до `app/` цього checkout; сам корпус у пакет
не копіюється. Можна переміщувати `.app`, поки checkout залишається на місці.
Після переміщення checkout перебудуйте пакет або запустіть бінарник із
`--corpus /новий/шлях/app`.

## Робочий процес

1. Знайдіть шрифт у бібліотеці. Є колекції та черги непереглянутих,
   змінених і шрифтів із неповною українською абеткою.
2. Виберіть одну чи кілька груп **Цифри**, **Латиниця**, **Українська**, **Пунктуація**,
   **Математика й валюти**, **Рамки й блоки** або **Усі групи** кнопками над
   плитками чи зі списку черг. Є також **Усі вихідні гліфи**, **Без Unicode**
   та **Змінені / додані**. Пунктирна плитка означає відсутній символ; її вибір
   лише показує порожнє полотно, не додає вигаданий гліф у джерело.
3. Ліва кнопка малює, права або гумка стирає. **Фліпер (F)** поруч із ними
   перемикає `0 ↔ 1`: і чорнило, і фон. Один штрих перемикає кожну відвідану
   клітинку лише раз, навіть при поверненні чи повторних pointer events.
   Новий клік може перемкнути її назад. ПКМ залишається гумкою. Швидке перетягування не залишає
   дірок; один штрих — одна операція undo. Масштаб цілий, без згладжування.
4. Для відсутньої літери введіть основу (`Г`, `U+0413`, `g000030`) і натисніть
   **Скопіювати гліф**, потім домалюйте пікселі. Доступні зсув із обрізанням,
   дзеркалення, повороти 90°/180°/270°, інверсія, очищення, розмір,
   горизонтальний крок, лівий відступ і зсув базової лінії.
5. Unicode-мапу можна додати до наявного немапованого гліфа або створити новий
   гліф для символу. Чужий уже зайнятий відповідник не замінюється мовчки.
6. **Переглянуто →** позначає гліф і переходить далі. **Шрифт переглянуто →**
   явно завершує перегляд шрифту й переходить до наступного. Це позначка
   людського перегляду, а не автоматична заява про повне українське покриття.
   Зміна гліфа скидає пов’язані позначки перегляду та статус шрифту.
7. Текстовий зразок показує поточні правки й рамки замість відсутніх символів.
   Лічильник українського покриття розділяє джерело та робочу правку.

Клавіші: `[`/`]` — гліфи; стрілки — зсув на 1 px, `Shift` + стрілка — на 10 px; `PageUp`/`PageDown` — шрифти;
`Enter` — переглянути й далі; `⌘Enter` — завершити шрифт; `B`/`E`/`F` — олівець/гумка/фліпер; `M`/`S` — зсув/масштаб растра; `R`/`L` — рамка/ласо;
`⌘C`/`⌘X`/`⌘V` — копія/вирізання/вставлення області; `⌘A` — виділити все;
`⌘D` — зняти виділення; `Delete` — стерти виділене;
`⌘Z`/`⌘Shift Z` — undo/redo; `⌘S` — негайне збереження; `⌘E` — експорт.
Гарячі клавіші прив’язані до фізичних позицій (`KeyboardEvent.code`), тож
працюють в українській, латинській та інших розкладках. Нативні ⌘-команди
також використовують фізичні коди клавіш macOS. Поля введення зберігають
звичайне введення тексту та текстові комбінації. Нативні меню підтримують
копіювання/вставлення та керування вікном.

## Канонічні групи й підписи

Групи мають сталий порядок: `0–9`, `A–Z`, `a–z`, українські великі й малі
(з Ґ/Є/І/Ї), пробіли/пунктуація, математика, валюти, рамки/блоки.
Кожна секція підписана. Відсутні символи показані пунктирними місцями;
вибір порожнього місця не записує нового гліфа до першої зміни.
Плитки підписані символами (`А · укр.`, `A · лат.`, `0`) або назвами
невидимих знаків (`Пробіл`, `Табуляція`). `U+…` та ID залишаються в tooltip
і докладних Unicode-мапах. Для гліфів без явної Unicode-мапи показується
вихідний код, а не вгаданий символ. Режим усіх вихідних гліфів зберігає
доступ до альтернативних форм і символів поза канонічними групами.

## Зсув і масштаб рисунка гліфа

**Зсув (M)**: перетягніть рисунок у комірці. Рух прив’язаний до цілих пікселів.
**Масштаб (S)**: тягніть вправо/вниз для збільшення, вліво/вгору для зменшення.
Золота рамка показує межі рисунка; червона означає вихід за край комірки.
Поруч з S є **Вісь: H+V / H / V**. H змінює лише ширину за горизонтальним
рухом, V — лише висоту за вертикальним; інша вісь залишається точно незмінною.
У H+V пропорції збережені за замовчуванням; `Shift` під час жесту або вимкнення
**Зберігати пропорції** дозволяє незалежну ширину й висоту.

Під час перетягування видно попередній растр; відпускання кнопки — одна
undo-операція, `Esc` або pointer-cancel — скасування без запису. Кожен кадр
обчислюється з початкових пікселів жесту: вихід за межі й повернення назад
до відпускання не втрачає пікселів і не накопичує похибок масштабування.
Перед збереженням, зміною шрифту/гліфа або закриттям активний жест завершується.

У правій панелі **Зсув і масштаб растра** є точні X/Y у пікселях, окремі
масштаби ширини/висоти (12,5–800 %) та опора — центр рисунка, верхній лівий кут
або базова лінія. **Застосувати до растра** записує всі параметри одним undo.
Порожні растри не масштабуються. Змінюються пікселі, комірка, advance,
bearings, shiftUp і Unicode-мапи зберігаються; пікселі за краєм після
застосування обрізані, їх повертає undo. Семплінг nearest-neighbor, без AA.
Масштаб **Вигляд** на панелі полотна лише збільшує зображення для редагування.

## Виділення, буфер і гайди

**Рамка (R)** виділяє прямокутник, **Ласо (L)** — довільну область.
Перетягування всередині виділення або інструментом M рухає тільки цю область;
S масштабує її пікселі й маску разом. Осі H/V працюють і для виділення;
точні відсотки/зсув у правій панелі теж застосовуються до активної області.
Кнопки **Дзеркало ↔ / ↕** на панелі полотна відображають ліво/право або верх/низ:
із виділенням — його пікселі й маску, без виділення — весь растр. Ті самі
операції доступні стрілками дзеркалення в інспекторі. Дзеркалення плаваючої
вставки залишається preview до Enter/збереження, Escape відкидає його. Стрілки без виділення рухають весь
рисунок, із виділенням — область; `Shift` дає крок 10 px. Область утримується
в комірці; цілий рисунок може обрізатися на краю, що показує preview.
Виділення скидається при зміні гліфа/шрифту та undo/redo; сам буфер залишається.

Копіювання/вирізання/вставлення працюють **між гліфами та між шрифтами**.
Системний буфер містить звичайний версійований JSON **Para Glyph Region 1.0**:
розміри, 1-бітні рядки, окрему маску форми та необов’язкове походження.
Див. [опис, приклад і JSON Schema](PIXEL-REGION.md). Можна вставляти JSON,
написаний вручну. Без виділення копіюється весь растр. У полях введення
нативні меню й комбінації зберігають звичайне копіювання тексту.

Вставлення спочатку створює плаваючу область: рухайте її стрілками/мишею,
потім **Enter / Закріпити**; **Escape** відкидає її. Це дозволяє дублювати
фрагмент без стирання його джерела. Збереження, закриття й навігація
дочікуються clipboard RPC та закріплюють видиму вставку. Один жест/вставка —
одна операція undo. Вирізання стирає лише маску; **Прозоро** пропускає нульові
пікселі при вставленні, без прапорця вони стирають ціль усередині маски.
Метрики та Unicode-мапи цілі зберігаються. Експорт записує джерело міжшрифтової
вставки, включно з font ID, SHA та license ID.

**Гайди** показують baseline гліфа, початок, advance, верх/низ комірки.
Верхні орієнтири великих H/Н і малих x/х вимірюються з реальних вихідних
гліфів; за відсутності таких основ їх не вгадують. Легенда показує координати
й колір кожної лінії. Гайди та виділення — лише накладки, у растр/експорт
вони не потрапляють.

## Автозаповнення двійників

**Автозаповнити А ↔ A** працює для поточного шрифту в обох напрямках.
Пари: `A/А B/В C/С E/Е H/Н I/І K/К M/М O/О P/Р T/Т X/Х`
та `a/а c/с e/е i/і o/о p/р x/х y/у`. Це копіювання пікселів і метрик,
а не транслітерація чи Unicode-нормалізація. Нижній регістр `b/h/k/m/t`
не включено, бо відповідні кириличні форми залежать від шрифту.

**Дзеркала й повороти…** показує геометричні заготовки з наявних гліфів:
`R↔Я`, `N↔И`, `Э↔Є`, `э↔є`, `b↔d`, `p↔q` (горизонтальне дзеркало);
`P↔Ь`, `p↔ь`, `L↔Г` (вертикальне); `b↔q`, `d↔p`, `n↔u`, `h↔ч` (180°);
`V↔Л`, `U↔П`, `v↔л`, `u↔п` (вертикальне відображення або 180°);
`L→Г`, `H→I`, `Н→І` (90°, зворотний напрямок — 270°).
Також є складені заготовки: `к + дзеркало(к) → ж` (або Latin `k`),
`К + дзеркало(К) → Ж` (або Latin `K`), `н + о → ю` (також Latin `o`),
`Н + О → Ю` (або Latin `H + O`). Потрібні всі явно маповані непорожні
компоненти; композиції не розкладаються у зворотному напрямку.

У `ж` дві половини мають спільну ніжку; латинська `k` обрізається по висоті
її діагоналей, щоб не переносити верхній виносний елемент. У `ю` беруться ліва
ніжка й перемичка `н`, а права ніжка замінюється овалом `о` з вирівнюванням
базової лінії. Компоненти підганяються до вихідної ширини піксельним відбором
без згладжування; надто вузькі/непридатні основи пропускаються. Розмір кроку
зберігається. Перегляд показує всі основи та точний растр майбутньої правки.

Усі варіанти спочатку пропущені; оберіть потрібні за переглядом растрів.
Для одного символу можна застосувати лише один варіант. Золота лінія
показує baseline, підпис — розмір і `shiftUp`. Після застосування доступна
ручна корекція в **Розмір і метрики → Застосувати розміщення**.
Геометрична схожість — підказка: шрифт може потребувати домальовування.

Обидві дії заповнюють відсутні Unicode-символи або один порожній джерельний
гліф без сторонніх Unicode-аліасів. Непорожні цілі, множинні варіанти та всі
вже редаговані цілі захищені, включно з навмисно очищеними вручну.
Основою може бути поточна правка. Числові вихідні коди без явної Unicode-мапи
не вгадуються. Дії не запускають ланцюгову генерацію в межах одного пакета.

Один пакет — одна операція **⌘Z** / **⌘Shift Z**; повторне застосування
не дублює символи. Позначки перегляду скидаються для змінених цілей;
автозаповнення не означає людського перегляду. Походження заготовки
(`sourceGlyphId`, символи, трансформація) зберігається в `derivations`
проєкту й у журналі експорту. Для композицій додатково записуються
`recipeVersion` та `components` з ID, символом і трансформацією кожної основи;
експорт перенумеровує також посилання на компоненти. Наступні ручні зміни зберігають початковий
рецепт, відновлення оригіналу прибирає його. Старі проєкти сумісні.

## Збереження та експорт

Правки зберігаються автоматично приблизно через 300 мс після штриха/дії,
перед переходом до іншого шрифту та перед закриттям вікна/завершенням програми.
Оригінальні файли корпусу ніколи не перезаписуються.

Проєкт: `~/Library/Application Support/VerbaGlyphEditor/Projects/<snapshot>/`.
`fonts/<font-id>.json` містить повні змінені гліфи, створені ID, Unicode-мапи,
позначки перегляду, нотатки та ревізію; `session.json` — останній вибір і фільтри.
Файли пишуться атомарно; старі ревізії та невідповідний source SHA відхиляються.
Блокування проєкту запобігає одночасному редагуванню у двох процесах.

**Експорт шрифту** і **Експорт усіх правок** створюють окремі повні JSON-файли
Para Font Interchange 2.0 у `exports/`. Вони мають `kind: derived`, власний ID,
вихідні ліцензії й походження та журнал ручних змін. Українське покриття
перераховується з реальних непорожніх растрів. Експорт не публікує правки в API
та не змінює pinned snapshot. Кнопка **Папка правок** відкриває ці файли у Finder.
Експорти мають унікальні імена; попередній експорт не затирається.

## Підкладка та гайди шрифту (0.8)

У правому інспекторі відкрийте **Підкладка / порівняння**. Додайте поточний
гліф або введіть інший символ, `U+…` чи `g000123` цього шрифту. Також працює
**Shift+клік** по гліфу в черзі без зміни редагованого гліфа. Блакитний знімок
залишається під рисунком під час навігації. Є видимість, непрозорість,
вирівнювання за baseline + початком пера або верхнім лівим кутом растра,
та зсув X/Y. Пікселі не масштабуються; зайве обрізається межами растра.
Підкладка — знімок на момент додавання, лише для поточного шрифту й сеансу.
Повторне додавання оновлює знімок; зміна шрифту прибирає його. Вона видима
у режимі «Правка», не потрапляє в undo, буфер обміну або експорт. Її растр
кешується під час малювання.

Кнопка **Гайди шрифту…** біля назви відкриває baseline, cap height, x-height,
ascent, descent та line gap. Кожна метрика має піксельну схему з кольоровою
стрілкою й поясненням. Порожні поля вмикають автовизначення для поточного шрифту: cap/x вимірюються з кількох відповідних літер, ascent/descent враховують їхні намальовані межі та метрики джерела, line gap — крок рядка. Аналіз кешується до зміни правок. Ручне значення має пріоритет. Значення задаються у px,
descent — додатна відстань униз. Зміни застосовуються до всього шрифту,
зберігаються окремо у `fontGuides` правок та переходять у Para `metrics`
експорту; після зміни ascent/descent/line gap обчислюється `lineHeight`.
Пікселі й метрики наявних гліфів зберігаються. Нові літери використовують спільну комірку та крок усього шрифту. Один Apply — один undo;
скидання до авто також можна скасувати. Можливий експорт тільки метрик,
без редагування гліфів. Джерельний корпус не змінюється.

один хибний піксель змінює форму; тому зменшення 96×96 зображення та поріг
не слід вважати готовим перенесенням стилю. Потрібні фіксовані cell/baseline,
перевірка зв’язності, товщини штрихів, розрізнення Ґ/Г, Є/Е, І/Ї/И та
дедуплікація кандидатів після приведення до фінального 1-bit растра.

Локальний каталог має 2 266 шрифтів, але лише 122 записи з ненульовим
українським покриттям, 62 повні за каталогом і 110 з ≥60 українськими літерами.
Варіанти 2y/жирності та спільні джерела не є незалежними шрифтами.
Тому train/test треба розділяти за сімейством і походженням, зберігати
джерельні ліцензії та відбирати лише придатні для конкретного експерименту
дані. Кількість усіх гліфів не дорівнює кількості українських прикладів.

Перший експеримент: на окремих сімействах приховати наявні ҐЄІЇЖЮЯґєіїжюя,
дати H/Н, x/х, о, н, к, р та інші структурно близькі референси, порівняти
геометричні/пошукові заготовки з FontDiffuser і невеликою умовною CNN.
Оцінювати top-4 прийнятність людиною, кількість ручних піксельних виправлень,
плутання символів, дублікати, час і пам’ять. Цільовий benchmark має включати
8×8, 8×16 та нерівномірні комірки. Для власної малої CNN вже є початковий benchmark у experiments/results.json;
FontDiffuser та MSD-Font на нашому корпусі ще не запускалися.

Інтеграцію варто відокремити від WKWebView: необов’язковий локальний worker
або окремий inference endpoint, а в UI — галерея кандидатів, Cancel,
перевірка актуальної ревізії перед Apply. Пакет запиту має містити font/source
SHA, target Unicode, cell/metrics, 1-bit референси, шаблон структури, seed і
кількість варіантів; відповідь — валідовані bitmap-кандидати з model/version,
seed, reference IDs та походженням. Прийняття не змінює Unicode, advance чи
baseline гліфа без окремої дії. Нові провайдери не мають блокувати малювання
та збереження. Для звичайної роботи редактор лишається автономним.

## Варіанти гліфа (0.9)

У правому інспекторі **Варіанти гліфа…** запускає локальну CNN та пошук
схожого шрифту. До восьми унікальних заготовок мають окремі позначки методу.
Можна підкласти кандидат під рисунок або вибрати й доредагувати одним undo.
Метрики та Unicode зберігаються; походження й ліцензія донора входять у journal.
Генерація працює окремим процесом, її можна скасувати. Застарілі результати
не застосовуються. Прототип потребує підготовленої локальної моделі, Python
із PyTorch та комірки/гліфа до 1024 px на вісь / 262144 пікселів; див. experiments/README.md. На цій машині
вже підготовлено модель і перевірено MPS. Нейронні заготовки з утраченими
штрихами відсіюються; пошукові лишаються доступні. Це експериментальна допомога.

## Перевірки

```sh
node --test desktop/glyph-editor/test.mjs
app/node_modules/.bin/tsc -p desktop/glyph-editor/tsconfig.json
node desktop/glyph-editor/build.mjs

# Кожна native-перевірка потребує окремого тимчасового проєкту:
GLYPH_TEST_PROJECT=$(mktemp -d)
'desktop/glyph-editor/dist/Verba Glyph Editor.app/Contents/MacOS/VerbaGlyphEditor' \
  --corpus "$PWD/app" --project "$GLYPH_TEST_PROJECT" --self-test --isolated-clipboard

# Справжній WKWebView + файловий bridge + бар’єр збереження перед завершенням.
GLYPH_SMOKE_PROJECT=$(mktemp -d)
'desktop/glyph-editor/dist/Verba Glyph Editor.app/Contents/MacOS/VerbaGlyphEditor' \
  --corpus "$PWD/app" --project "$GLYPH_SMOKE_PROJECT" --smoke --isolated-clipboard
```

122 модельні тести перевіряють широкі рядки/padding, суцільні штрихи,
undo/redo, додавання українського гліфа, Unicode-мапи, трансформації,
інвалідацію перегляду, безпечні двійники/геометричні заготовки, пакетний undo,
повороти прямокутних растрів і сумісний експорт зі збереженням ліцензії/джерела
та рецептів заготовок, композиції ж/ю, потрібні повороти V/U/h, залежності
й перенумерацію всіх компонентів, зсув/масштаб растра, опори, вихід за край
і повернення, межі віртуального масштабу та канонічний експорт мутацій;
порядок канонічних регіонів, відсутні слоти, аліаси, людські підписи й відсутність
припущень про Unicode для сирих кодів.
Вони й typecheck додані до Linux CI. Native self-test перевіряє атомарний
round-trip, заборону старих ревізій/чужого SHA та виходу за межі корпусу.

Ручна/браузерна перевірка на окремому тестовому проєкті підтвердила реальний
штрих мишею, undo/redo, review-next, відновлення після перезапуску й експорт.
Згенерований файл пройшов штатний `validateFont`; source SHA не змінився.
`--smoke` підтвердив запуск саме WKWebView та збереження перед завершенням.

Для інструментальної перевірки того самого UI/файлового сервісу є локальний
HTTP transport: `--serve-preview 8800 --resources <пакет>/Contents/Resources`.
Для перевірок clipboard додайте `--isolated-clipboard`: він використовує
окремий іменований буфер та не змінює особистий системний буфер.
HTTP transport слухає лише `127.0.0.1`, вимагає same-origin POST і призначений для розробки;
звичайний `.app` не відкриває порт і використовує WKScriptMessageHandler.

## Межі першої версії

Між шрифтами зберігаються правки, але undo-історія стосується поточного шрифту;
вона обмежена 128 діями та 8 MiB. Растр гліфа — до 1024 у кожному вимірі,
не більше 262 144 пікселів; це покриває всі поточні джерела (до 770×144).
Автозаповнення запускається користувачем для поточного шрифту;
геометричні варіанти потребують вибору за переглядом. Вивід — канонічний JSON;
компіляція TTF/OTB і публікація у корпус — окремі подальші дії.
