# Verba API: одна угода для всіх корпусів

Дата: 2026-11-25. Статус: рішення Дмитра внесено (2026-11-25); чекає погодження документа.
Попередня специфікація: [verba-umbrella](2026-11-02-verba-umbrella.md) (спільний вхід і навігація).

## 1. Навіщо

Парасолька дала спільний вхід, але нижче вхідної сторінки кожен корпус живе окремо:
свої формати, свої ID, свої копії чужих даних. Орнаменти у Verba взяті трьома
різними способами (жоден — з актуального `patterns.v3.json`), шрифти рамок UPA
живуть окремо від Nasinnia, «Без табу» не має API.

Мета — **догфудинг**: усі власні продукти (сайт-парасолька, Telegram-бот, картки
для соцмереж, сайт UPA) беруть прислів'я, слова, шрифти й орнаменти **тільки через
публічне API**, тим самим шляхом, що й сторонні користувачі. Якщо щось незручно
зробити через API — це дефект API, а не привід для обхідного шляху.

Це основа для трьох пріоритетів Дмитра (листопад 2026): публікації в соцмережі,
парасолька `verbacorpus.org`, сайт UPA.

## 2. Обсяг

Корпуси: `pro` — прислів'я (`verbacorpus`), `contra` — «Українська без табу»
(`ua-bez-tabu`, дані синхронізуються у Verba), `para` — шрифти Nasinnia
(`nasinnia`) разом зі шрифтами рамок UPA (`upa-archive/data/font-library`),
`non` — орнаменти UPA (`upa-archive`).

**Цілі**
- Одна угода для всіх корпусів: глобальні ID, однакова обгортка відповіді, однаковий
  мінімальний набір ендпоїнтів, ліцензія на кожному записі.
- Шлюз `api.verbacorpus.org` (Worker `verba-api`), що говорить цією угодою.
- `random` для кожного корпусу й наскрізний; відтворюваний через `seed`.
- Картка-композиція: текст (`pro`/`contra`) + рамка-орнамент (`non`) + шрифт (`para`)
  як JSON-рецепт, SVG і PNG.
- API для «Без табу» зі стабільними ID.
- Verba бере орнаменти тільки з API UPA; три теперішні способи прибираються.
- Шрифти рамок UPA реєструються в Nasinnia; UPA читає їх звідти.
- Піксельні іконки прибираються з `non.verba` (див. §8).

**Не-цілі**
- Наскрізний семантичний пошук по всіх корпусах.
- Планувальник і автопублікація в соцмережі — наступний проєкт, що стоятиме на цьому API.
- Сувій/texted, редактор гліфів (`verbacorpus-para-fonts`), `zbizhzhia`, піксельні іконки.
- Зміна моделей даних джерел заради уніфікації.

**Анти-цілі** (провал, навіть якщо технічно працює)
- Шлюз або Verba тримають власні копії даних інших корпусів — знову розсинхрон.
- Ламаються наявні `/api/v1/*`, `/p/*`, `/s/*`, `/card/*`, `/bez-tabu/*` прислів'їв.
- Ліцензія одного корпусу «протікає» на інший (CC BY 4.0 прислів'їв не поширюється на решту).
- Через API назовні йде те, що не погоджено до публікації: PDF, скани, `metadata-only`
  растри Nasinnia (Hoard). Орнаменти UPA й записи «Без табу» йдуть з атрибуцією за §5.3,
  без заявленої ліцензії.
- Власні продукти мають «внутрішній» обхід API.

## 3. Обмеження

- Новинний cron Verba лишається вимкненим; зберігається тільки `0 6 * * *`.
- Зберегти bindings Verba: `AI`, Vectorize `proverbs-bge-m3-v2`, `NEWS_KV`, `UPA`.
- Жодних токенів і секретів у документах чи git.
- UPA: видимість GitHub, історію git, DNS, реєстри пакетів не змінювати без рішення власника.
  Не заявляти ліцензію, яку не надано.
- `editorial/` у Verba не комітиться без перегляду.
- `ua-bez-tabu` — репозиторій на іншому акаунті (`MurzikVasilyevich`).
- Nasinnia зараз без git remote і з незакоміченими змінами; Verba — 72 незакомічені файли
  на `integrate/bez-tabu`. Робота над API не починається поверх незафіксованого стану (§9, крок 0).

## 4. Підходи

| | Суть | Плюси | Мінуси |
|---|---|---|---|
| **А. Угода + шлюз** (обрано) | Кожен корпус лишає свій Worker і дані; спільна угода; шлюз через service bindings додає наскрізне | Одне джерело правди на корпус; наявні Workers і binding UPA лишаються; нове — лише шлюз і API «Без табу» | Ще один Worker; нормалізація форматів у шлюзі |
| Б. Центральне API у Verba | Verba імпортує все в себе | Найпростіші запити | Дублювання даних, знімки, розмите джерело правди — саме те, від чого йдемо |
| В. Без шлюзу | Споживачі ходять напряму до кожного API | Найменше роботи | Нема єдиної угоди; random і картки повторюються в кожному споживачі |

## 5. Угода

### 5.1 Глобальні ID

`<корпус>:<локальний-id>`, корпус ∈ `pro`, `contra`, `para`, `non`. Локальний ID — той,
що джерело вже має:

| Корпус | Приклад | Звідки |
|---|---|---|
| pro | `pro:p037464` | `id` прислів'я |
| non | `non:p07_L_b00` | `patternId` UPA |
| para | `para:cozette-13x15` | `fontId` Nasinnia |
| contra | `contra:<стабільний-id>` | **ще не існує**: `sourceRow` нестабільний (§7) |

Підресурси через `/`: `para:cozette-13x15/U+0456` — гліф. ID у шлюзі — непрозорі рядки;
шлюз їх не переписує, лише додає префікс.

### 5.2 Обгортка відповіді

Список:
```json
{ "apiVersion": "v1", "corpus": "non", "total": 167, "limit": 50, "offset": 0,
  "nextOffset": 50, "items": [ ... ] }
```
Запис:
```json
{ "id": "non:p07_L_b00", "corpus": "non", "title": "…",
  "licence": { "id": "CC-BY-4.0" | null, "status": "granted" | "terms-pending" | "metadata-only",
               "attribution": "…", "url": "…" },
  "links": { "self": "https://api.verbacorpus.org/v1/non/items/p07_L_b00",
             "html": "https://non.verbacorpus.org/upa/catalog?page=7#p07_L_b00" },
  "data": { …рідний запис джерела без змін… } }
```
Помилки: `{ "error": { "code": "not_found", "message": "…" } }` з відповідним HTTP-статусом.

### 5.3 Права й атрибуція за корпусами (рішення Дмитра, 2026-11-25)

| Корпус | `licence.id` | `status` | Атрибуція | Картки / наскрізний random |
|---|---|---|---|---|
| pro | `CC-BY-4.0` | `granted` | як зараз у Verba | так |
| non | `null` | `terms-pending` | «Hough, 2025 / Габданк-Рогозинський» | так, геометрія й рамки дозволені |
| contra | `null` | `terms-pending` | Л. Ставицька, «Українська мова без табу» | **лише за явним `corpus=contra`** |
| para | з запису Nasinnia | `granted` або `metadata-only` | з запису | тільки `granted` з повною абеткою |

MIT репозиторію `ua-bez-tabu` покриває лише код, не матеріал книжки, — у `licence.id` його не ставити.
Записи `metadata-only` не віддають растрів і не потрапляють у картки.

### 5.4 Ендпоїнти шлюзу

```
GET /v1/corpora                         реєстр (з app/content/corpora.json) + живі лічильники з /meta
GET /v1/{corpus}/meta
GET /v1/{corpus}/items?limit&offset&…    фільтри джерела проходять наскрізь
GET /v1/{corpus}/items/{localId}
GET /v1/{corpus}/random?n&seed&…
GET /v1/items/{globalId}                 резолвер будь-якого ID
GET /v1/random?corpus=pro,non&n&seed     наскрізний random (без corpus — усі, крім contra)
GET /v1/cards/random?seed&format         випадкова картка
GET /v1/cards?text=pro:…&frame=non:…&font=para:…&size=square|story|wide&format=json|svg|png
GET /v1/openapi.json, /v1/docs
```

`seed` робить вибір детермінованим (той самий seed → той самий результат): для тестів,
для «картки дня» і щоб допис можна було перегенерувати.

### 5.5 Хто що реалізує

- **Шлюз нормалізує** формати джерел адаптерами (по одному на корпус). Від джерел потрібні
  лише список з `limit/offset`, запис за ID і `meta`. `random` шлюз уміє зробити сам
  (випадковий offset), а якщо джерело має свій `random` з фільтрами — використовує його.
- **pro**: наявне `/api/v1/*` Verba; без змін, крім рамки й шрифту в картках (§6).
- **non**: наявне `/upa/api/v1/patterns`; UPA додає ендпоїнт смуги/рамки з орнаменту для карток (§6).
- **para**: Nasinnia — **єдине** джерело шрифтів (§8); растри тільки для записів, дозволених до поширення.
  `para.verbacorpus.org/fonts`, який зараз обслуговує UPA, переходить на Nasinnia.
- **contra**: нове API (§7).
- Шлюз ходить до джерел через service bindings: `PRO` (Worker Verba), `UPA` (`upa-local-preview`),
  `FONTS` (`nasinnia`).
- Шлюз не має власного сховища даних. Кешування — Cache API з короткими TTL; `random` без `seed` — `no-store`.

## 6. Картки

Verba вже рендерить картки (`app/src/card.ts`, `card-gif.ts`: PNG/GIF, 1080², 1080×1920,
1280×720, 512²), але рамку бере з власних 38 бордюрів (`app/src/shader/embroidery.ts`),
а текст пише PT Serif.

Нова модель:
- **Рецепт** — JSON `{ text: id, frame: id, font: id, size, palette }`; рецепт сам є
  відповіддю `format=json` і може зберігатися в дописі як «звідки ця картка».
- **Рамка** — геометрію орнаменту будує UPA (там уже є `frame-service`/`strip-service`);
  Verba лише компонує. Палітра — з кольорів UPA (A–G), фон B.
- **Шрифт** — гліфи з Nasinnia. Для українського тексту годяться тільки шрифти з повним
  покриттям абетки й дозволом на поширення (на сьогодні — `cozette-13x15`, MIT); відсутній
  символ показується явно, без тихої заміни. **Рішення Дмитра (2026-11-25):** бітмап-шрифт
  з Nasinnia — за замовчуванням; PT Serif — параметром і запасним варіантом.
- Рендер залишається у Worker Verba; шлюз делегує через binding.
- На кожній картці — атрибуція всіх трьох складників згідно з їхніми ліцензіями.

## 7. API «Без табу»

- Живе у Worker Verba поруч із наявними `/bez-tabu/*` (дані вже синхронізуються
  `app/sync_bez_tabu.py`); шлюз бачить його як корпус `contra`.
- Потрібен стабільний ID запису. `sourceRow` не годиться. ID обчислюється детерміновано з
  нормалізованих полів запису й фіксується в окремій таблиці відповідності Verba
  (`app/content/bez-tabu-ids.json`), щоб ID не «з'їжджали» при оновленні джерела. `entries.json`
  не змінюється — його хеш закріплений у `provenance.json`. Дублікати рядків джерела зливаються в один запис.
- Ендпоїнти: `meta`, `items` (з фільтрами за групою/терміном), `items/{id}`, `random`.
- Права — за §5.3: атрибуція Л. Ставицькій на кожному записі, `licence.id = null`.

## 8. Інші зміни, що з цього випливають

**Орнаменти у Verba.** Прибрати:
- `app/public/data/embroidery-archive.json` і `app/scripts/build-embroidery-archive.mjs`
  (абсолютний шлях у `dyco`);
- 38 вшитих бордюрів у `app/src/shader/embroidery.ts` → курований список **ID** UPA
  (у Verba лишаються тільки ID, не матриці);
- `editorial/telegram/ornaments/` → генерується через API. **Рішення Дмитра (2026-11-25):**
  `editorial/` лишається поза комітами; старі згенеровані орнаменти прибираються після переходу на API.
`app/src/embroidery-css.ts` переходить на ті самі ID.

**Уся бібліотека шрифтів UPA → Nasinnia** (рішення Дмитра, 2026-11-25). Це не лише 22
шрифти рамок з `upa-archive/data/font-library` (`docs/TEXTED-FONTS.md`), а вся бібліотека,
яку зараз віддає `para.verbacorpus.org/fonts` (2 266 записів, з них 319 з растрами, 1 947 —
Hoard metadata, які в Nasinnia вже є під іншими ID).
- Nasinnia — єдине джерело; UPA і Verba читають шрифти тільки з його API.
- Старі ID UPA лишаються **псевдонімами** в Nasinnia, щоб збережені `upa:document:v1` не зламались.
- Похідні шрифти (13 українських похідних UPA, re-cell `cozette-13x15`) приймаються з полем
  «походить від» (ID предка) і власним описом змін; ліцензія — від предка.
- Дублікати Hoard зводяться до одного запису; другий ID — псевдонім.
- Шрифти рамок позначаються призначенням «рамки».

**Піксельні іконки.** Прибрати з `non.verba`: сторінку `/non/icons/`, експорти, пункт
навігації, згадку в реєстрі `corpora.json`. `app/content/pixel-icons.json` лишається в
історії git; до іконок повернемось окремим проєктом.

**Знімки.** Після переходу на API `sync_corpora.py` і знімки метаданих UPA/Nasinnia
стають непотрібними для рантайму. Лічильники на сторінках беруться з `/v1/corpora`.

## 9. Порядок

0. **Гігієна** (рішення Дмитра, 2026-11-25).
   - Verba: розкласти 72 незакомічені зміни `integrate/bez-tabu` на логічні коміти, **без `editorial/`**;
     PR у `main`; уся подальша робота — від `main`.
   - Nasinnia: закомітити поточний стан; remote — **приватний** репозиторій `dmytro-yemelianov/nasinnia`.
1. **Угода + шлюз (лише читання)** над `pro`, `non`, `para`: `corpora`, `meta`, `items`,
   `random`, резолвер, OpenAPI. Спільний набір контрактних тестів, що проганяється проти кожного корпусу.
2. **API `contra`** зі стабільними ID; підключення до шлюзу.
3. **Наскрізний `random`** із `seed`.
4. **Картки** через рецепт; Verba переходить на орнаменти з UPA і шрифти з Nasinnia;
   старі способи прибираються; іконки прибираються.
5. **Шрифти рамок** у Nasinnia; UPA читає звідти.
6. **Догфудинг**: сайт-парасолька, бот і сторінки беруть дані тільки через шлюз; перевірка,
   що прямих звернень до чужих даних не лишилось.

**Розгортання входить у проєкт** (рішення Дмитра, 2026-11-25): по одному Worker у порядку
UPA → Nasinnia → Verba → шлюз (`api.verbacorpus.org`), кожне — тільки після окремого «так»
Дмитра. Перед кожним: `--dry-run`, перевірка bindings і cron Verba, план відкату (попередня версія Worker).
`upa-local-preview` — той самий Worker, з яким пов'язаний робочий Verba, тож його зміни мають бути
зворотно сумісні з наявним binding.

## 10. Перевірки

- Контрактні тести: однаковий набір для кожного корпусу (обгортка, ID, ліцензія на кожному записі, 404, пагінація).
- Тести шлюзу з підробленими bindings; детермінованість `seed`.
- Регресія старих URL прислів'їв і «Без табу».
- Тест, що записи `metadata-only` не дають растрів і не потрапляють у картки; `contra` не потрапляє
  в наскрізний random і випадкові картки без явного запиту; кожна картка несе атрибуції складників.
- Псевдоніми шрифтів: усі старі ID UPA резолвляться; збережений `upa:document:v1` відкривається.
- Візуальна перевірка карток у всіх розмірах; українські символи; явний відсутній гліф.
- `wrangler deploy --dry-run` для кожного Worker; cron Verba не змінився; після кожного розгортання —
  перевірка наживо тих самих контрактних тестів проти продакшн-адреси.

## 11. Лишається будівельнику

Рішення, які я ухвалив сам (можна заперечити): нормалізацію робить шлюз (джерела міняються мінімально);
API `contra` живе у Worker Verba; рендер карток лишається у Verba, геометрію рамки дає UPA;
стабільний ID `contra` обчислюється при синхронізації з таблицею відповідності.

Також будівельнику: зіставлення `upa_<hash>` ID 38 бордюрів Verba з `patternId` UPA; перетворення
`page/perPage` Nasinnia на `limit/offset`; напрям викликів шлюз ↔ Verba для карток; стабільність `seed`
при зміні даних.

Структура коду шлюзу і де він лежить у репо Verba; конкретні TTL кешу; формат OpenAPI;
алгоритм стабільного ID `contra` (у межах §7); бібліотека рендеру PNG (продовжити наявну);
обмеження частоти запитів, якщо знадобиться.

## 13. Статус реалізації та верифікація (2026-11-27)
