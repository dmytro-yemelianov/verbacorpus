# Para Glyph Region 1.0

Версійований текстовий формат растрового фрагмента. Той самий JSON працює
в системному буфері macOS, файлі `.glyph-region.json` та повідомленні.
**Копія / ⌘C** у редакторі записує цей JSON; **Вставити / ⌘V** читає його.
Можна копіювати між гліфами й шрифтами, а також вставити JSON, написаний вручну.
Звичайне копіювання тексту в полях введення залишається стандартним.

## Мінімальний приклад

Скопіюйте весь об’єкт і натисніть **Вставити** у редакторі. Це хрестик 3×3;
маска повторює його довільну форму, тому чотири кути не торкаються цільового растра.

```json
{
  "format": "para-glyph-region",
  "schemaVersion": "1.0.0",
  "bitmap": {
    "encoding": "hex-rows",
    "bitOrder": "msb-first",
    "bitsPerPixel": 1
  },
  "width": 3,
  "height": 3,
  "rowBytes": 1,
  "rows": ["40", "E0", "40"],
  "maskRows": ["40", "E0", "40"]
}
```

[JSON Schema](pixel-region.schema.json) описує структуру;
[готовий приклад](pixel-region.example.json) можна скопіювати без Markdown.

## Пікселі та маска

`width`/`height` — розміри обрізаного фрагмента; `rowBytes = ceil(width / 8)`.
`rows` та `maskRows` мають по `height` рядків, кожен довжиною `rowBytes * 2`
hex-символів. Найлівіший піксель — старший біт першого байта. Наприклад,
`40 = 01000000`, `E0 = 11100000`; для ширини 3 останні п’ять бітів — нуль.

- Біт `1` у `rows` — чорнило, `0` — фон.
- Біт `1` у `maskRows` — вибрана позиція; `0` — поза виділенням.
- Позиції поза маскою не застосовуються. Експорт обнуляє там приховані пікселі.
- Для прямокутника 3×3 маска була б `["E0", "E0", "E0"]`.
- Режим **Прозоро** пропускає фонові нулі; без нього нулі всередині маски
  стирають відповідні пікселі цілі. Поза маскою ціль завжди зберігається.

Розміри — 1–1024 по осі, площа — до 262 144 пікселів, текст — до 512 KiB.
Маска мусить містити хоча б одну вибрану позицію. Некоректні типи, версії,
hex-рядки, padding і розбіжності розмірів відхиляються до вставлення.
JSON Schema перевіряє структуру; `parseRegion` додатково перевіряє ці
міжпольові умови. Дробові пікселі та згладжування не використовуються.

## Необов’язкове походження

`origin` зберігає `fontId`, `glyphId`, `sha256` вихідного запису шрифту та
`licenseId`; додатково — `char`, `draftRevision`, `baseline`, `advanceX` і
`rectangle: {x, y, width, height}` у координатах вихідного гліфа.
Поля `origin` описують джерело, а не змінюють метрики цільового гліфа.
Вони не потрібні для фрагмента, намальованого вручну.

Якщо немає цільового виділення, вставлення бере вихідну позицію й вирівнює
baseline, коли ця інформація доступна; інакше починає з (0, 0).
Активне цільове виділення задає місце вставлення. Фрагмент можна пересунути
стрілками або мишею, масштабувати інструментом S, закріпити Enter чи відкинути
Escape. Закриття, збереження або навігація закріплюють видиму вставку.
Метрики й Unicode-мапи цілі зберігаються. Походження міжшрифтової вставки
записується в журнал похідного експорту; source ID чужого шрифту не
перенумеровується як локальний.
